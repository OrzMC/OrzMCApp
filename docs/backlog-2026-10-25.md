## 优先级总览

| # | 事项 | 优先级 | 成本 | 风险 | 归属 |
|---|---|---|---|:--|---|
| 1 | 远程托管「偶现错误弹窗」：把原始 `NSError` 甩给用户、取消也当错误 | **P0** | 0.5h | 低 | app ✅ |
| 2 | 详情页控制台空态占位跑到左下角 | P1 | 20m | 低 | app ✅ |
| 3 | 内存区「分配内存」标签与 stepper 分成两行 | P1 | 30m | 低 | app ✅ |
| 4 | 「我的服务器」列表菜单：编辑/删除冗余、选中态、点击热区 | P1 | 1h | 低 | app ✅ |
| 5 | iOS 没有应用图标（发版阻塞项） | P1 | 1h | 低 | app ✅ |
| 6 | 统一终端渲染组件（ANSI 颜色/控制字符） | P2 | 4–8h | 中 | app ✅（+ 设计文档） |
| 7 | 多供应商（Exaroton + MCSM）+ 多实例：先设计后实现 | P2 | 调研 2h + 实现 1–2 天 | 中高 | app + 文档 |

放行顺序建议：**1 → 2+3+4（一个 PR）→ 5 → 6 → 7**。
理由：1 是"看起来像崩溃"的打扰（且泄内部信息）；2/3/4/5 都是低风险小而可见；6/7 需要设计与跨模块改动，
适合单独会话推进。

## P0-1 远程托管错误弹窗（截图 IMG_2743）— ✅ 已修复（2026-10-25）

**结果**：新增 `OrzMC/Common/ExarotonUI/Model/RemoteHostingErrorText.swift`
（`kind(of:)` 分类 + `describe(_:)` 出一句人话，取消 → `nil`），
所有远程托管错误的调用点改走它（额度池、内存读取/保存、生命周期动作、三条 WS 流操作）；
额度池卡片加 `remote.creditPoolCard` 标识，新增真机/模拟器用例
`testRealCreditPoolReentryNeverAlerts`（连进出 20 次断言零弹窗）。

**验证**：`OrzMCTests` 新增 9 条（取消/超时/401/403/503/兜底不泄露 `NSError`）；
`scripts/dev/check.sh` 全绿；`run-ios-ui-tests.sh` 全绿（含新用例 20 轮、真实账号）。

现象：弹窗标题「远程服务器错误」，正文是原始 NSError：

```
Failed to fetch credit pool info: Client encountered an error invoking the operation
"getCreditPool", caused by "Transport threw an error.", underlying error:
Error Domain=NSURLErrorDomain Code=-999 "已取消" UserInfo={NSURLErrorFailingURLStringKey=https://api.exaroton.com/v1/billing/pools/..., …}
```

两个问题：

1. **-999 是"任务被取消"**（视图消失 / `ConnectionEpoch` 换代 / 请求被换掉），不是错误，应该静默；
2. 即使是真错误，也**不该把 `localizedDescription` 直接给用户看**（英文、嵌套、URL、内部类名）。

改法（建议）：

- 新增 `RemoteHostingErrorText.describe(_ error:)`（参照 `SelfHosted/SelfHostedErrorText.swift` 的写法）：
  - `CancellationError` / `URLError(.cancelled)` / `NSURLErrorCancelled(-999)` → `nil`（**不弹**）
  - 网络类（`.notConnectedToInternet` / `.timedOut` / `.cannotConnectToHost`）→ 「网络不可用，请稍后重试」
  - 401/403（token 失效）→ 「账号 Token 已失效，请重新登录」
  - 5xx / 其他 → 「服务暂时不可用（HTTP xxx）」
- 调用点归一：`ExarotonServerModel+HTTP.swift` 里 `errorMessage = "Failed to fetch credit pool info: \(error...)"` 这类
  直接拼字符串的地方全部改走上面这个函数；`errorMessage == nil` 时不弹 alert。
- 有单测：`OrzMCTests` 里加 4–6 条（取消 → nil、超时 → 文案、401 → token 文案）。

涉及文件：`OrzMC/Common/ExarotonUI/Model/ExarotonServerModel+HTTP.swift`、新增 `…/Model/RemoteHostingErrorText.swift`、
`OrzMC/Common/Localizable.xcstrings`。

验收：连续进出详情页 / 切换额度池 20 次不出现弹窗；断网时出现**一句中文**而不是 NSError 转储。

## P1-2 控制台空态占位位置 — ✅ 已修复（2026-10-25）

**结果**：空态**不再进滚动视图**（`if empty { 固定高度面板 } else { ScrollView }`），
面板内 `VStack + Spacer` 顶对齐；顺带给日志内容加了 4pt 内边距，占位与日志首行位置一致
（以前文字直接贴着圆角边框）。给面板/占位加 `remote.consolePanel` / `remote.consolePlaceholder`
标识，新增 DEBUG 钩子 `ORZMC_DEMO_EMPTY_CONSOLE=1`（假 live 时不再塞日志）。

**验证**：`testConsoleEmptyStateSitsTopLeft` —— 用面板像素统计断言「顶部有字、底部无字、偏左」
（Form 会把行内子视图合并成一个无障碍元素，量 frame 判不出位置）。



现象：控制台区域没有日志时，「等待服务器输出…」贴在左下角。

原因：占位放在 `ScrollView` 里，而外层用了 `.defaultScrollAnchor(.bottom)` → 空内容被推到下方；
`VStack + Spacer` 的组合在 `LazyVStack`/`ScrollView` 里也不按预期撑开。

改法：空态**不进滚动视图**（`if empty { placeholder } else { ScrollView { … } }`），
占位用 `.frame(maxWidth: .infinity, maxHeight: .infinity, alignment: .topLeading)` + 内边距，
与日志首行对齐（左对齐、顶部），或用 `.padding(.top, 8)` 让它在顶部。

涉及文件：`OrzMC/Common/ExarotonUI/List/ExarotonServerDetail.swift`（`Section("Console")`）。

验收：截图快照（`testSnapshotRemoteConsole`）里占位在左上角，与首行日志位置一致。

## P1-5 iOS 应用图标 — ✅ 已修复（2026-10-25）

**结果（与建议的"逐尺寸生成"不同，用了更省事且不会漂的做法）**：
`AppIcon.appiconset/Contents.json` 里本来就有一条 `idiom: universal / platform: ios / 1024x1024`
（Xcode 14+ 的**单尺寸**图标），macOS 与 iOS 因此可以共用同一个图标集：

1. iOS target 的 `ASSETCATALOG_COMPILER_APPICON_NAME` 改回 `AppIcon`（删掉
   `[sdk=iphone*]` 指向 `AppIcon-iOS` 的覆盖）；
2. 删掉那个**一个 png 都没有**的 `AppIcon-iOS.appiconset`（它就是 iOS 没图标的根因）；
3. `appstore1024.png` 重新导出为**不含 alpha**（iOS 图标不允许 alpha；原文件 alpha 全 255，
   视觉无损），Xcode 由它派生 40/58/60/80/87/120/180/1024 等全部尺寸。

**验证**：`xcodebuild`（iOS Simulator）无 icon/asset 警告；产物里出现
`AppIcon60x60@2x.png` / `AppIcon76x76@2x~ipad.png`，`CFBundleIcons.CFBundlePrimaryIcon`
指向 `AppIcon`；模拟器主屏能看到与 macOS 一致的「黑底绿方块」图标。


现状：`OrzMC/Common/Assets.xcassets/AppIcon-iOS.appiconset/Contents.json` 存在但**没有任何 png**（字段为空），
所以 iOS 上没有图标，与 macOS 不一致。

改法：

1. 从 `AppIcon.appiconset/mac1024.png`（或源图）生成 iOS 所需尺寸：1024、180、167、152、120、87、80、76、60、58、40、29、20（@2x/@3x）；
2. 写进 `AppIcon-iOS.appiconset` 并补 `Contents.json` 的 `filename`；
3. 确认 `ASSETCATALOG_COMPILER_APPICON_NAME` 在 iOS target 指向 `AppIcon-iOS`（macOS 指向 `AppIcon`）；
4. 装到真机看一眼主屏。

可用 `sips`（无第三方依赖）：

```bash
sips -z 180 180 mac1024.png --out Icon-60@3x.png   # 示例；逐尺寸生成
```

验收：真机主屏与 macOS Dock 图标一致；`xcodebuild` 无 "app icon set has unassigned children" 警告。

## P2-6 统一终端渲染组件（ANSI）— ✅ 已修复（2026-10-25）

**结果**：三层落地，设计/规则见 [`console-rendering.md`](console-rendering.md)。

1. **解析（`Sources/OrzMCFoundation/ConsoleText.swift`，纯逻辑）**
   `ConsoleTextParser.parse/plainText/lines(in:)/trimmingWhitespace`：
   ANSI SGR（0/1/22/30–37/39/90–97/38;5;n/38;2;r;g;b，背景色吃掉不渲染）、
   Minecraft `§0–§f §l §r`、`\r` 行内覆盖、`\r\n`、多行拆分、其余 CSI/OSC/控制字符丢弃。
   按 **Unicode 标量**遍历（Swift 把 `\r\n` 当一个 Character，按字符比较会漏）。
2. **渲染（`Sources/OrzMCDesignSystem/ConsoleText.swift`）**
   `ConsolePalette` 按 `ColorScheme` 调色（黑白族取对比色、黄压成琥珀、真彩色按亮度微调），
   `ConsoleLineText` 用 `AttributedString` 一次成型（等宽 + 加粗），**不引入 WebView**。
3. **三个控制台收口到同一渲染**
   - macOS 本地服务端：`ServerConsoleBuffer` 不再剥色，`ConsoleLine.segments`；
   - 自建服务器 RCON：`ConsoleLine.segments` + 兜底色（命令行=强调色、错误=危险色）；
   - exaroton：`RemoteConsoleBuffer` 支持"一条消息多行"并解析颜色，上限常量化（2000 行）。

**验证**：`swift test` 105 → 新增 20 例解析单测 + 4 例缓冲区（颜色/多行/`\r`/空白）；
`scripts/dev/check.sh` 全绿；iOS UI 用例
`testConsoleRendersANSIColorsWithoutEscapeResidue`（样本行带真实 ANSI/`§`，断言渲染后无残留）
与截图确认红/黄/绿正确。



现象：控制台把服务端输出按纯文本显示，带 ANSI 颜色码/控制字符（`\u001B[32m`、`§`、`\r` 覆盖行）时很脏。

调研方向（建议写进 `docs/console-rendering.md`）：

- **解析层**：写一个纯 Swift 的 ANSI SGR 解析器（颜色 30–37/90–97、粗体、重置；`\r` 行内覆盖；
  其余控制序列直接丢弃）。纯值类型 + 单测，不依赖 UI。
- **渲染层**：`ConsoleTextSegment { text, color?, bold? }` → SwiftUI `Text` 拼接（`AttributedString` 或
  多个 `Text` 连接），等宽字体；不引入 WebView（性能与选型都不合适）。
- **作用面**：自建服务器控制台（`SelfHostedServerView.consoleLog`）与 exaroton 控制台
  （`ExarotonServerDetail` 里 `model.consoleLines` 的渲染）共用同一个组件；
  顺带把 320 行的 `RemoteConsoleBuffer` 上限与"跟随底部"逻辑一起收口。

验收：对着真实 Paper 服务器看彩色日志（INFO/WARN/ERROR）颜色正确、无 `\u001B` 残留；
单测覆盖常见 SGR 组合与畸形序列。

## P2-7 多供应商 / 多实例（Exaroton + MCSM）

目标：远程托管能从"只支持 exaroton 单账号"扩展为**多供应商 + 每供应商多实例（多账号/多面板）**。

调研要点：

| 维度 | Exaroton | MCSM（MCSManager） |
|---|---|---|
| 认证 | API Token（`Authorization: Bearer`） | 面板 `apikey`（`X-Request-API-Key`）+ 用户登录 |
| 实时状态 | 官方 WebSocket（本次已封装成状态中心） | 无 WS；`/api/instance` 轮询 + 守护进程状态 |
| 生命周期 | start/stop/restart | `/api/protected_instance/start|stop|restart` |
| 控制台 | WS console 流 | 无推送；`/api/protected_instance/output` 轮询日志 |
| 命令 | WS `console` + `command` | `/api/protected_instance/command` |
| 内存 | `/servers/{id}/ram` | 实例 config（`maxMemory`） |

设计草案（先出 `docs/remote-hosting-providers.md`，再动手）：

```swift
protocol RemoteHostingProvider {
    var kind: ProviderKind { get }              // .exaroton / .mcsmanager
    func listInstances() async throws -> [RemoteInstance]
    func start(_ id: InstanceID) async throws
    func stop(_ id: InstanceID) async throws
    func sendCommand(_ id: InstanceID, _ command: String) async throws
    func statusEvents() -> AsyncStream<RemoteStatusEvent>   // 复用现有状态中心
}
```

- **凭据**：一个供应商可存多份凭据（exaroton token 多账号 / MCSM 面板 URL+apikey+用户），
  全部进 Keychain（参照 `SelfHostedCredentials` / `KeychainStore` 的做法）；
- **状态中心**：把 `ExarotonServersModel` 里的 `publishStatus/statusEvents/RemoteStatusRefreshPolicy`
  抽成与供应商无关的 `RemoteStatusCenter`（**这次已经有雏形**，见
  `OrzMC/Common/ExarotonUI/Model/ExarotonStatusCenter.swift`），供应商只负责"喂数据"；
- **UI**：远程托管列表按供应商分组（或加 provider 过滤），卡片上显示供应商徽章；本地（自建）仍然是另一套。

先做 MCSM 的**只读**接入（列实例 + 状态轮询），再做动作与命令，最后才做多账号管理界面。

验收：新增一个 MCSM 面板（URL + apikey）能在同一个"远程托管"页里看到实例并实时看到状态变化；
切换/删除账号不影响其他账号的轮询。
