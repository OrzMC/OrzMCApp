# 页面与导航交互审查

> 状态：P1/P2 源码改进已实施；Air 当前会话完成部分 AX/交互验收，视觉与真实运行状态验收未完成｜核验日期：2026-10-22
> 方法：apple-native-product-design、swiftui-pro、swift-concurrency-pro；审查当前未提交工作树。

范围包括主启动器、Launch、Settings、内嵌/独立控制台及 Exaroton 列表与详情。macOS 最低目标为 14；共享远程 UI 的 iOS target 为 18。建议保留现有目标与单主启动器 Window，不以升级系统要求换取新 API。

证据边界：本轮直接在 Air 运行进程读取 Accessibility 树并操作 UI；未截图、未运行 VoiceOver，也未取得当前布局图像。Air SSH 不可达，本轮不能重新构建；上次 macOS/iOS 成功构建记录见交接日志。美观、960/1200pt 下的实际布局与中文截断仍需维护者桌面视觉核验。

## 值得保留的基础

- 单主窗口、按实例独立控制台、独立远程窗口，符合当前模型所有权。
- 系统 NavigationSplitView / Form / Settings、语义色与 consoleSurface 已形成统一基础。
- 高危动作收进菜单、状态同时使用文字和颜色、文本字段采用行标签加示例 prompt，方向正确。

## 1. P1：本地控制台 Follow 会抢回滚动位置

位置：`OrzMC/Launcher(MacOS)/UI/Detail/ServerConsoleView.swift:192`。

代码在每次新增行后，只要 followOutput 为 true 就 scrollTo；没有观察用户离开底部。用户上滚查看旧日志仍会被下一条日志拉回，与属性注释描述不符。每次输出还强制执行 0.1s 动画，没有减少动态效果分支。

建议：只在用户停留于底部时自动跟随；上滚后暂停，显示“回到最新”按钮和新增行计数；搜索期间保持阅读位置，清空搜索时按明确规则恢复。批量追加日志时合并一次滚动，并尊重 Reduce Motion。macOS 14 的实现应使用可用的底部哨兵/位置观测；不要直接使用更高版本 API 而不作兼容处理。

验收：持续输出时上滚、选择复制、多次搜索，阅读位置不跳；点“回到最新”恢复跟随。

## 2. P1：远程生命周期操作没有请求期间的互斥与局部反馈

位置：`OrzMC/Common/ExarotonUI/List/Components/ExarotonServerActionSection.swift:101`；`Model/ExarotonServerModel+HTTP.swift:29`；`ExarotonContent.swift:25`。

perform 创建 Task，但未设置 isLoading 或 pendingAction；可用性依赖尚未更新的远程状态。网络慢时可重复提交。成功又通过全局 statusMessage 弹出必须关闭的确认框，打断连续操作。

建议：请求开始前同步记录实例级 pendingAction，禁用冲突动作；按钮显示“正在请求启动…”，接收成功显示非模态状态，真正运行状态由服务端更新确认。不能在 HTTP 请求被接受时直接显示“已运行”。错误保留可重试入口，并在请求结束时释放忙碌状态。

示意：当前 `Task { await request() }` 改为“先设置 pendingAction → 执行请求 → defer 清除请求状态”；它应由模型防重入，不能只依赖按钮 disabled。

验收：限速网络下连续点击仅发一次；返回列表后状态仍一致；成功无需额外点 OK。

## 3. P1：设置目录输入每改一个字符就执行目录切换

位置：`OrzMC/Launcher(MacOS)/UI/Settings/SettingsView.swift:26`、`:66`；`Model/AppModel.swift:83`。

TextField 直接绑定 AppModel.rootDir。setter 更新设置、重算安装状态、刷新 Java/服务器并重置启动进度。输入尚未完成的路径也会成为实际目录；频繁扫描还可能影响输入响应。

建议：字段使用本地草稿，验证后在 Return/“应用”提交；选择目录和恢复默认可直接提交。保留正在编辑的文字，错误显示在字段附近，Escape 恢复已提交值。磁盘扫描是否占用主线程需单独测量，不能仅凭这里断言已有卡顿。

示意：`TextField(text: $rootDir)` → `TextField(text: $draftRootDir).onSubmit(commitValidatedRoot)`。

验收：逐字输入长路径不刷新目录；无效路径不落入设置；成功提交只刷新一次，已有运行实例仍可管理。

## 4. P1：远程日志清空只改显示副本，旧内容会回来

位置：`OrzMC/Common/ExarotonUI/List/ExarotonServerDetail.swift:116`、`:219`。

“清空”只设置 consoleLog = ""；下一次日志回调又从 model.consoleLines 全量 joined，旧日志重新出现。另外 `model.consoleLine.publisher` 是 Optional 的一次性 Publisher，不是持久观察流；在它上面 throttle 不能可靠表达一个长期日志流的节流设计。

建议：日志以一个缓冲模型为事实源，清空清理缓冲或保存可见起点；用显式观察或持续 AsyncSequence 接收日志，按批次更新稳定 ID 的行。不要通过重复拼接整段字符串实现流式控制台。

验收：清空后新增一行，旧日志不会重现；连续输出下可以选择文本、上滚；停止/重连后的日志保留规则明确。

## 5. P2：内嵌控制台与侧边栏选中项缺少明确的导航关系

位置：`OrzMC/Launcher(MacOS)/UI/Detail/BasicInfo.swift:248`、`:264`。

consoleTarget 保存在 BasicInfo 的局部 State；切换版本时没有显式重置。于是侧边栏可选 B，而详情仍展示 A 的控制台。按实例固定控制台本身合理，但内嵌导航应明确用户正在查看谁。

建议：主窗口切换版本时返回该版本详情；需要固定观察 A 时使用已有独立控制台窗口。不要用重建 AppModel 或修改主 Window 为 WindowGroup 解决此问题。

验收：打开 A 控制台后选择 B，详情立即展示 B；A 独立控制台继续连接，返回导航不混乱。

## 6. P2：远程列表的空、失败和账号状态需要区分

位置：`OrzMC/Common/ExarotonUI/List/ExarotonServerList.swift:74`、`:131`、`:166`。

空态固定提示添加 Token；已登录但没有服务器、请求失败没有拿到列表时，也可能看到同一说明。刷新按钮没有防止并发加载，多个请求共用 isLoading，先完成者可提前关闭加载提示。

建议：分别展示未配置账号、加载中、已加载为空、请求失败、已有数据刷新失败；后者保留原列表并提供重试。加载在模型内串行或采用请求版本校验，避免旧响应覆盖新账号数据。初次无 Token 可优先显示清晰 CTA，避免每次进入都自动弹账号表单。

验收：无服务器、无网络、无效 Token、快速刷新和更换账号都有明确且稳定的反馈。

## 7. P2：Launch 的压缩需要兼顾横向对齐和文字完整性

位置：`OrzMC/Launcher(MacOS)/UI/SideBar/GameView.swift:82`、`:113`、`:126`、`:149`。

客户端使用 LabeledContent，服务端使用手工 HStack；模式控件固定 170pt，Start 固有宽度且不可压缩，进度文案固定一行中间截断。代码能确认布局约束存在，但没有截图，尚不能断言某种窗口宽度实际溢出。

建议：保留三行启动区；客户端与服务端配置统一使用 LabeledContent/一致标签列；横向不足时让次要内容换行。进度拆成完整阶段名与可截断路径，明确“正在安装 Java / 下载资源 / 启动进程”，不要只展示忙碌图标。启动中保留区块占位，避免出现/消失时整体跳动。

验收：主窗口最小宽度、960/1200pt、中文长版本名与输入焦点环；按钮文字完整，字段基线一致，进度关键阶段可读。

## 8. P2：远程内存更改需要提交顺序与失败回退

位置：`OrzMC/Common/ExarotonUI/List/ExarotonServerDetail.swift:208`。

Stepper 的变化立即触发无持有句柄的 Task；返回结果又写入 serverRAM，失败时没有显式恢复 confirmedRAM。缺少提交状态和响应顺序约束，不利于表达“期望值”和“已保存值”。

建议：Stepper 编辑草稿，明确提交；或以单一在途任务串行提交最新期望值，失败保留错误与重试/恢复入口。不要认为设置了 Task 就能获得取消传播或自动防重入。

验收：快速加减、请求失败、操作中返回再进入，UI 显示值始终能解释是否已保存。

## 视觉与页面组织建议（待截图验证）

- 主启动器：保持版本导航 → 当前版本启动 → 实例内容的顺序；一个区块内突出一个主要动作，减少所有生命周期图标等权并排。
- 控制台：生命周期、搜索、导出、清空、独立窗口目前集中在工具栏。优先保留当前有效主动作与搜索，将低频/破坏性动作收进菜单，960pt 下检查工具栏溢出。
- Settings：保留四页系统结构。调整各页输入区的共同最小宽度，避免把 560×480 固定尺寸作为长中文和大字号的唯一布局；保留可滚动内容，并评估是否允许窗口增长。
- Remote Servers：当前单 NavigationStack 在 Mac 上每次详情返回列表。若用户频繁切服务器，可评估仅 macOS 使用列表/详情双栏，iOS 保留现有栈；这是导航方案提案，不是必须重构。960pt 检查最小布局，1200pt 检查过长表单行。
- 状态语言：离线是中性状态；连接中、认证失败、网络断开分别表达。当前远程工具栏把“尚未 ready”统一显示红色断云并重复 pulse，建议等待中用中性进度，真正失败才用错误状态，并提供重连入口。
- 所有动效先服务状态变化：系统转场优先，日志自动滚动避免连续动画，尊重减少动态效果。语义色、亮暗模式与提高对比度继续沿用 OrzMCTheme；暂不需要增加品牌色或大面积玻璃装饰。

### 1. 控制台 Follow（对应 §1）

- 新增 `Sources/OrzMCLauncher/ConsoleFollowState.swift`：跟随 / 暂停 / 未读 / 搜索四态的状态机；视图只负责渲染与滚动。
- 规则明确化：上滚即暂停并累计未读；**用户自己滚回底部自动恢复跟随并清零未读**（程序滚动不触发，见 `NSScrollView.didLiveScrollNotification`）；搜索期间暂停跟随；结束搜索不自动恢复（保留阅读位置）；「回到最新」= 退出搜索 + 恢复跟随 + 滚动。
- 「回到最新」的滚动改为等状态生效后再执行（`scrollToLatestToken` + 追加一次布局后补滚），避免清空搜索时滚到被过滤的旧行集；动画仍尊重 Reduce Motion，连续输出不带动画。
- 测试：`swift test --filter ConsoleFollowState`（9 例，覆盖默认跟随、上滚暂停计数、滚回恢复、搜索不跟随、清空搜索不自动恢复、显式回到最新、开关关闭、无未读时滚回也恢复、非正数追加）。
- 仍需人工：真实日志下的上滚/复制/搜索手感、满 2000 行缓冲、关闭再打开控制台；本机未截图。

### 2. 远程生命周期动作：互斥与失败反馈（对应 §2）

- 新增 `Sources/OrzMCRemoteHosting/RemoteActionGate.swift`：实例级在途互斥，生命周期动作与内存变更互相排除，**在首次 await 之前占用**，请求结束（成功或失败）即释放；不同实例互不阻塞。
- 模型改为持有一个 `gate`：`pendingActions` / `pendingMemoryChanges` 由 `gate` 提供，视图只读；换账号时 `gate.reset()`。
- 三个生命周期端点收敛到同一实现（占用 → 请求 → 判定 → 释放），避免三份实现漂移；成功只承诺「已提交启动/停止/重启请求」，运行状态仍以服务端推送为准。
- 失败不再弹必须确认的全局框：错误留在动作区（`actionErrors`）并以 `OrzMCBanner(.error)` 展示，请求结束即可点 `Retry` 重发同一动作；响应非 2xx / `success != true` / 传输错误分别给出可读原因（细节附在括号里）。
- 测试：`swift test --filter RemoteActionGate`（5 例：同日实例重复提交被拒、生命周期与内存互斥、实例间互不影响、结束后可重试、reset 清空）。
- 仍需人工：真实 exaroton 账号下的限速/失败路径（需 token 与额度），以及返回列表后的状态一致性。

### 3. RAM 保存失败行为（对应 §8）

- 卡片标题栏 = `启动` + **主按钮**（`启动客户端 / 启动服务端`）。按钮始终在同一个位置，不需要滚到底、也不需要先把类型选完才"看见"启动。
- 进度/就绪状态在标题栏紧邻按钮；分段进度文案与错误 banner 仍在卡片内。

### 2. 用 `Grid` 固定列宽，取代 `LabeledContent`

「总是对不齐」的根因：`LabeledContent` 依赖表单的标签列，而分段控件 / 菜单 / 输入框各有不同内边距，混排必然错位；宽窗口下标签列还会被拉宽。
现在启动面板是一个 `Grid(alignment: .leadingFirstTextBaseline)`，标签统一 `frame(width: 96)`、控件列统一起点；服务端核心也从"菜单"改为**分段控件**，一行里全是同类"选项片"。

### 3. 行序 = 操作序，且面板不塌缩

| 行 | 客户端 | 服务端 |
|---|---|---|
| 模式 | `客户端 / 服务端` + `Vanilla / Fabric` | `客户端 / 服务端` + `Paper / Vanilla / Fabric / Forge` |
| 账户 | 玩家名输入框 | 一句说明「服务端不需要玩家名。」（**行不消失**，面板高度稳定） |
| Java | 已装版本 → 需要版本 + 状态徽标 + 重新扫描 | 同左 |
| 主按钮 | 标题栏右侧 | 同左 |

### 快捷键返工：本地事件监听 + 单行输入框也让路（2026-10-22，第八轮补 3）

维护者反馈「快捷键不生效」。自测（`--test-keys` 向应用事件队列投递按键）定位到两个原因：

1. `.onKeyPress` 挂在 `List` 上时，只有列表自己拿到键盘焦点才触发；侧边栏里焦点常在搜索框，于是"不生效"。
2. 第一版监听把"正在编辑文本"整体放行，而**搜索框默认就持有焦点** → 所有方向键都被跳过。

改法（`SideBar/VersionListKeyboardNavigation.swift`）：

- 用 `NSEvent.addLocalMonitorForEvents(matching: .keyDown)` 装**应用内本地监听**：只要主窗口在、没有 sheet 在弹，↑/↓ 与 ⌘↑/⌘↓ 就作用于版本列表；
- **只有多行编辑器**（`TextEditor`，`NSTextView.isFieldEditor == false`）才放行方向键；单行输入框（搜索框、用户名、路径、令牌）里 ↑/↓ 本来就是无用操作，交给列表导航——事件被 consume，输入内容与光标都不受影响（与 Finder / Xcode 的过滤框行为一致）；
- ⌘↑/⌘↓ 仍挂在 Game 菜单（`跳到最新版本` / `跳到最旧版本`）供发现与免焦点使用。

**自测证据**：投递 ↓ / ↓ / ⌘↓ 后，选中项从 26.3 变为列表末尾的 `1.0`（2011-11-18），列表自动滚到底、详情页标题同步变成 `Minecraft - 1.0`。日志确认 `handled down (jump=false/true)` 三次。

仍需维护者手动确认的是"真实键盘手感"（`--test-keys` 只验证监听与选中逻辑，不验证键位冲突）。

### 首/末跳转的滚动到底问题（2026-10-22，第八轮补 4）

维护者反馈：⌘↓ 只切换选中项，列表没有滚到真正的底部（末尾留白看不到），顶部的 ⌘↑ 同理。

**根因（实测确认）**：`ScrollViewReader.scrollTo(id, anchor:)` 对**懒加载**的 `List` 只能落到"估算位置"，
跳到很远的行时会稳定差几行；加 `.bottom` 锚点、加动画、连续补几次都不能收敛。

**改法**：`SideBar/VersionListScrollProbe.swift` —— 拿到 `List` 背后的 `NSScrollView` + `NSTableView`：

- 探针放在列表背景里，按**窗口坐标**在视图树中找"包住它的 NSTableView 滚动视图"
  （`enclosingScrollView` 找不到：SwiftUI 的 List 不是背景层的祖先）；
- `scrollToBottom()` / `scrollToTop()`：先 `tableView.scrollRowToVisible(目标行)` 让表格把目标行实例化，
  再按「当前文档高度 − 视口高度」贴边，重复 5 轮直到收敛（懒加载表格的文档高度是边滚边长的）；
- 中间行仍然用 `proxy.scrollTo(id)` 做最小滚动。

**自测证据**（`--test-keys` / `--test-keys-top` 向应用投递按键）：
- ⌘↓ → 最后一行 `1.0`（2011-11-18）完整可见，列表底下留白也露出来；日志 `row=102 doc=3112 clip=524 y=2588` ×5 收敛；
- ⌘↑ → 首行 `26.3` 完整可见（紧贴更新时间下方）；日志 `row=0 … y=0` ×5。

### 详情页展示模式 + 表头动作自适应（2026-10-22，第十三轮）

（含操作按钮那一行）；操作按钮在行内按竖线分组、尽量全部展示，只有空间不足时才收进「更多」。

**做法**
- 顶部右侧一个分段控件「全部折叠 / 全部展开」，值存 `@AppStorage("orzmc.detail.allExpanded")`，
  **默认折叠**：一屏能看到一个版本的全部 6 个实例（2 客户端 + 4 服务端），不用滚动。
- `InstanceSection` 增加 `isExpanded`：折叠时只渲染表头（面板高度 ≈ 一行），展开时才渲染分隔线与目录行。
- 表头动作改成**自适应**：`Sources/OrzMCLauncher/HeaderActionPlan.swift`（纯逻辑 + 6 个单测）
  按「按钮数 × 28pt + 组内间距 + 组间竖线 + ⋯ 按钮」估算，从"全部内联"开始，放不下时依次把
  `danger`（终止/删除）→ `lifecycle`（启动/重启/停止）收进 `⋯`，最后才只剩 `⋯`。
  可用宽度由表头右端容器背景的 `GeometryReader` 量出（容器 `maxWidth: .infinity`，所以量到的就是剩余空间）。
- 因此 **960pt 窗口下 7 个按钮（控制台/插件/启动/重启/停止/终止/删除）全部内联**；
  窄到约 200pt 时变为「控制台 插件 ｜ ⋯」——用 `ORZMC_ACTION_SPACE=200` 复现验证过。

**约定**：动作按钮的可见性由**空间**决定，不由"危险程度"决定；高危动作不再默认隐藏（仍带二次确认）。

### 单栏折叠/展开（2026-10-22，第十四轮）

维护者意见：除了「全部折叠 / 全部展开」，每一张客户端/服务端卡片也要能单独折叠展开。

**做法**
- 表头标题左侧加一个 ⌄/› 箭头，**标题本身也是按钮**（点哪都行，命中区域是整个标题）：
  `Button { toggleAction?() }`，`.buttonStyle(.borderless)`，带上 `Collapse this instance` / `Expand this instance`
  的帮助与辅助功能标签。
- 状态模型：`@AppStorage allExpanded` 是**默认值**，`@State expansionOverrides: [实例 id: Bool]` 是**单栏覆盖**；
  展开状态 = `expansionOverrides[id] ?? allExpanded`。
  - 切换全局模式 → 清空覆盖（回到统一状态）；
  - 切换版本 → 清空覆盖（实例 id 里含版本号，旧键本来也不会命中）。
- 实测：全局「全部折叠」下点「客户端（Vanilla）」标题，只有该栏展开（⌄ + 目录行），其余仍折叠；
  全局「全部展开」下每栏都是 ⌄。

**新调试入口**：`--test-click x,y`（窗口坐标，从左上角算，单位 pt），向应用自身事件队列投递一次鼠标点击，
用来回归"只能靠鼠标触发"的交互（这次就是靠它验证的单栏折叠）。

### 折叠卡片上下边距对称（2026-10-22，第十四轮补）

维护者指出：折叠状态下的卡片"上下边距不对称"。

**测量**（对 960×740 截图逐像素扫描，卡片边框与文字 ink 各自定位）：
- 原值 `padding(.top, 14) / .padding(.bottom, 10)` 是给**展开态**定的（表头下面紧跟分隔线），
  但折叠态整张卡片只有这一行 → 实测 ink 距上边 33px、距下边 23px，差了 5pt，肉眼就是"文字偏上"。
- 改成折叠态 12/12 后：ink 距上 28px、距下 29px（差 0.5pt，处在抗锯齿噪声内），卡片总高 40pt 不变。

**约定**：只有一行的卡片，上下内边距必须相等；有多行时"表头底部"可以小于"表头顶部"，
因为分隔线本身也算视觉重量。改这类间距时用 `/tmp/scan`、`/tmp/ink2` 这类逐像素扫描确认，不靠目测。

### 全部展开/折叠改成图标动作 + 修"点了没反应"（2026-10-22，第十五轮）

**Bug**：单栏折叠/展开之后再点「全部折叠」没反应。原因是控件是 `Picker` 绑 `allExpanded`：
单栏覆盖不会改变 `allExpanded`，所以点"当前已选中的那一档"不会触发 `onChange`，覆盖也就没被清掉。

**修法**：改成**两个动作按钮**（不是状态选择器）——每次点击都显式 `allExpanded = ...` + `expansionOverrides = [:]`，
任何状态下点都生效：
- `rectangle.compress.vertical` → 全部折叠
- `rectangle.expand.vertical` → 全部展开
- 图标态（30×22，`borderless`），外面套一层 `subtleFill` 胶囊；**当前全局档位有底色**，
  存在单栏覆盖时两档都不高亮（= 混合状态），tooltip 与辅助功能标签仍是完整文案。

**实测**（`--test-click` 连续点击）：
- 全局折叠 + 点开一张卡 → 再点"全部折叠" → 所有卡片回到折叠 ✓
- 全局展开 + 收起一张卡 → 再点"全部展开" → 该卡重新展开 ✓

**约定**：这类"作用于全体"的入口一律用**动作按钮**，不要用状态 `Picker`——
状态选择器在"局部被单独改过"的场景下会静默失效。
